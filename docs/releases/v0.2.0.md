# v0.2.0（2026-09-22）

这一版补上了「接外部工具」和「长对话不爆」两块：M5 MCP 客户端、M6 上下文工程都已完成，
M4 定时任务做了第一步（任务定义）。另外加了 debug 模式，工作台的回复改成 Markdown 渲染，
并且把同一台机器上的开发环境和日常环境彻底隔开。

## 这一版新增了什么

### 接 MCP server（M5）

- 手写的 MCP 客户端，不依赖官方 SDK，分四层：stdio 传输 → 协议会话 → 包装成 `Tool` → 多 server 管理。
- 在 `config.toml` 里写 `[mcp_servers.<名字>]`，它的工具就以 `mcp__<名字>__<工具>` 出现在模型面前，
  REPL、`sa run`、`sa serve` 都能用；另有 REPL 的 `/mcp` 和 `sa mcp list` 查看状态。
- 新旧两代协议都支持：MCP 规范 2026-07-28 取消了 `initialize` 握手，客户端先用 `server/discover`
  探测，不行再退回 `initialize`。
- 权限：server 标了只读（`readOnlyHint`）的工具免确认，其余要确认，可以按工具覆盖。
  **工作目录边界管不到 MCP 工具**，边界由 server 自己的参数决定。
- 密钥：server 子进程只拿到白名单环境变量，需要 token 的写 `env_vars = ["NAME"]`，值不进配置文件。
- server 崩溃后下次调用时自动重启（5 分钟内最多 3 次）；单个 server 起不来不影响其他的。

### 上下文工程（M6）

- **预算**：上次请求的实际用量 + 之后新增部分的字符估算，再用校准系数修正。`/context` 看占用和构成。
- **三级策略**：写入时截断（M2 已有）→ 占到 60% 时清理旧工具结果（原文落盘，可读回）→
  占到 80% 时让模型把早期对话压成摘要（切点不拆开 tool_call 和它的结果）。阈值在 `[context]` 里配。
- **前缀缓存**：摘要请求复用上一次请求的前缀，实测 DeepSeek 缓存命中从 30%～58% 提到 95%～97%。
- `/compact [重点]` 手动压缩；服务端报「上下文超长」时自动压缩一次再重试。
- 修复：REPL 的 `/clear` 之前没落盘，`--resume` 后历史又回来；工作台中断工具后留下悬空的 `tool_call`，
  下一条输入会被 API 拒绝。工作台的会话历史拆成「展示用」和「给模型用」两份，老会话第一次用到时自动迁移。

### 定时任务定义（M4 第 1 步）

- `schedules.toml` 定义任务：`[jobs.<名字>]` 里写 `cron`、`prompt`、`profile`、`cwd`、`allowed_tools`、
  `notify` 等。单个任务写错只影响它自己。
- `sa schedule list` 列出每个任务的下次触发时间，写错的任务标出原因。
- `sa init` 改成「缺哪个配置文件就生成哪个」，老用户再跑一次就能补上 `schedules.toml` 模板。

### debug 模式

- 四档 `off / on / verbose / full`：on 看每次 API 请求和工具调用的概要，verbose 再加消息清单，
  full 再加实际发给模型的正文和模型返回的结构（跨轮只打新增的部分）。
- 三个入口：`config.toml` 的 `[debug]`、`sa --debug [LEVEL]`、REPL 里的 `/debug`。
- debug 输出走 stderr，可以 `2>debug.log` 单独存。

### 工作台

- 空间会话里模型的回复改用 Markdown 渲染（零依赖手写渲染器）：标题、列表、任务列表、表格、代码块、链接。
  只有 `http(s)` 链接可点，**图片不加载**，防止 prompt injection 借图片 URL 把数据外发。

### 开发环境和日常环境隔离

- 日常用的 `sa` 改为从 GitHub 装快照：`uv tool install "git+https://github.com/tjiisztiuv/SimpleAgent.git@v0.2.0"`，
  本地改代码不影响它。
- 在源码仓库里 `uv run sa` 是开发模式：数据目录自动换成 `~/.simpleagent-dev/`，`sa serve` 默认端口换成 8385，
  两边可以同时开；`sa --version`、REPL 和 `sa serve` 启动时都会标出来。
- 优先级：`SIMPLEAGENT_HOME` > 开发模式 > `~/.simpleagent`。

## 升级

```bash
uv tool install --reinstall "git+https://github.com/tjiisztiuv/SimpleAgent.git@v0.2.0"
sa --version                     # simpleagent 0.2.0
sa init                          # 补上 schedules.toml 模板（config.toml 已存在会跳过）
```

- 之前用 `uv tool install --editable .` 装的，也用上面这条换成快照，否则日常用的就是开发中的代码。
- `config.toml` 里的新段（`[context]`、`[debug]`、`[mcp_servers.*]`）都有默认值，不加也能跑；
  要看完整说明，对照 `sa init` 生成的模板（见 `src/simpleagent/config.example.toml`）。
- 工作台的老会话第一次打开时自动迁移成两份历史，不用手动处理。

## 已知限制

- **定时任务还不会自己跑**：M4 只做了任务定义，`sa daemon`、通知、`web_fetch` 都还没做，
  这一版仍要自己用 cron / launchd 调 `sa run`。
- **MCP 只支持本机 stdio server**：远程 HTTP 和 OAuth 的 server（日历、邮件、IM 大多是这种）
  等引入官方 `mcp` SDK 时再做。
- **权限规则还没进配置文件**，`--allow` 只认工具名，不支持模式匹配。
- **外部 CLI 执行者没有实时审批**：Claude Code / OpenCode 的空间仍只有只读和全放行两档。
- debug 的 full 档正文不推给工作台前端，只在终端里看。
- 记忆、Skills、子 agent 都还没做，见 [路线图](../ROADMAP.md)。

## 下一步

M4 剩下的步骤：跑一次任务和运行日志 → 通知 → `web_fetch` → `sa daemon` → 让模型管理任务的工具 → launchd 常驻。
