# v0.2.0（2026-09-22）

这一版补上了「接外部工具」和「长对话不爆」两块：M5 MCP 客户端、M6 上下文工程都已完成，
M4 定时任务做了第一步（任务定义）。另外加了 debug 模式，工作台的回复改成 Markdown 渲染，
并且把同一台机器上的开发环境和日常环境彻底隔开。

对比基线是 v0.1.0（`772d411`，2026-09-18）。每一批改动到函数级的明细见文末「详细变更记录」。

## 一览

| 类别 | v0.1.0 → v0.2.0 |
|---|---|
| 新命令 | `sa mcp list`、`sa schedule list`、`sa --debug [LEVEL]`（`sa run` 也认） |
| REPL 新命令 | `/mcp`、`/context`、`/compact [重点]`、`/debug [off\|on\|verbose\|full]` |
| 新配置段 | `config.toml` 的 `[context]`、`[debug]`、`[mcp_servers.<名字>]`；新文件 `schedules.toml` |
| 新运行时依赖 | `croniter>=6.2`（带进 `python-dateutil`、`six`）；原来只有 `openai`、`pydantic` |
| 新数据目录 | `mcp_cache/`、`tool_outputs/cleared-*.txt`、`spaces/<id>/sessions/model/`；开发模式用 `~/.simpleagent-dev/` |
| 新事件 / SSE 帧 | `ApiRequest` / `ApiResponse`（帧 `api_request` / `api_response`）、`ContextEdited`（帧 `context_edited`） |
| 仓库地址 | 换到 `github.com/tjiisztiuv/SimpleAgent`，日常安装改为从 GitHub 装快照 |
| 测试 | 314 → 604 个，全部离线 |

## 这一版新增了什么

### 接 MCP server（M5）

手写的 MCP 客户端，不依赖官方 SDK，分四层：stdio 传输 → 协议会话 → 包装成 `Tool` → 多 server 管理。

- **配置**：在 `config.toml` 里写 `[mcp_servers.<名字>]`，它的工具就以 `mcp__<名字>__<工具>` 出现在模型面前，
  REPL、`sa run`、`sa serve` 都能用。可配的项：`command`、`args`、`env`、`env_vars`、`cwd`、`enabled`、
  `start`、`protocol`、`startup_timeout`、`tool_timeout`、`enabled_tools` / `disabled_tools`（只暴露部分工具）、
  `trust_annotations`、`permissions`（按工具覆盖权限）。server 名只能用字母数字、`-` 和单个 `_`，最长 24 字符
  （要拼进工具名）。
- **协议**：新旧两代都支持。MCP 规范 2026-07-28 取消了 `initialize` 握手，客户端先用 `server/discover` 探测
  （10 秒），不行再退回 `initialize`；`protocol = "auto" | "modern" | "legacy"` 可以写死。`tools/list` 自动翻页；
  工具结果里的文本、图片、音频、资源都转成给模型看的文本；新协议的「版本不支持」「缺客户端能力」等错误转成可读说明。
- **启动**：`sa` / `sa run` / `sa serve` 启动时并行拉起所有 server，单个起不来不影响其他的。
  REPL 等全部有结果再接受输入，卡住的可以按 Ctrl+C 跳过；`sa run` 的状态摘要写 stderr，不混进正文，
  server 起不来只警告、不影响退出码。`sa serve` 所有空间、所有会话共用同一批 server 子进程。
- **按需启动**：server 配 `start = "lazy"`（默认 `"eager"`）后，sa 启动时直接用上次连上时缓存的工具清单
  （`mcp_cache/<名字>.json`）登记工具、不拉起进程，模型第一次调用它的工具时才真正启动。
  缓存带启动参数指纹，command / args / env 等变了就作废；第一次还没缓存时照常启动一次。
- **查看状态**：`sa mcp list` 把每个 server 真的启动一遍，列出状态和工具再关掉（不需要 API key，
  有失败时退出码为 1，懒启动的也会连一遍并刷新缓存）；REPL 里 `/mcp` 看协议代际、工具数、schema 大小、重启次数。
- **权限**：server 标了只读（`readOnlyHint`）的工具免确认，其余要确认，可以用 `permissions` 按工具覆盖；
  确认时显示针对这个工具的说明。`sa run` 里要用 `--allow mcp__<名字>__<工具>` 逐个放行。
  **工作目录边界管不到 MCP 工具**，边界由 server 自己的参数决定。
- **密钥**：server 子进程只拿到白名单环境变量（`HOME`、`PATH`、`LANG`、代理等），需要 token 的写
  `env_vars = ["NAME"]`，值放环境变量或 `.env`。`env` 里出现像密钥的键名（含 `KEY`、`TOKEN`、`SECRET`、
  `PASSWORD` 等）直接报错，且不回显值。
- **崩溃与关闭**：server 中途退出后，下次调用时自动重启（5 分钟内最多 3 次）；退出时正在执行的那次调用
  不自动重试，交给模型决定。关闭时按「关 stdin → SIGTERM → SIGKILL」的顺序清理整个进程组，
  `npx` 拉起的 `node` 子进程一起清掉。
- **server 说明**：server 返回的 `instructions` 截到 2000 字、标明是第三方内容后追加进 system prompt。

### 上下文工程（M6）

- **预算**：上次请求的实际用量 + 之后新增部分的字符估算，再用校准系数（实际用量 ÷ 同一段的字符估算）修正。
  REPL 的 `/context` 显示总量、精确和估算各占多少、构成、估算误差。
- **三级策略**：
  1. 写入时截断（M2 已有）。
  2. 占到 `clear_at`（默认 60%）时清理旧工具结果：原文落盘到 `tool_outputs/cleared-<摘要>.txt`，
     模型可以读回；最近几个（`keep_tool_results`，默认 3）、模型还没看过的、太短的、读回过的都不清。
     能省下的不到输入上限的 5% 就不清，尽量少打破前缀缓存。
  3. 占到 `compact_at`（默认 80%）时让模型把早期对话压成摘要，保留最近约 1/4；切点不拆开 tool_call 和它的结果。
- **前缀缓存**：摘要请求复用上一次请求的前缀，实测 DeepSeek 缓存命中从 30%～58% 提到 95%～97%。
  清理和压缩同时要做时先压缩再清理，避免白清。
- `/compact [重点]` 手动压缩，完整保留最后一轮，可以附带要保留的重点。
- 服务端报「上下文超长」（400 / 413，按各家报错的关键字认）且这一步还没输出内容时，自动压缩一次再重试，每步只重试一次。
- 清理和压缩发生时，REPL 和 `sa run` 显示一行提示，工作台收到 `context_edited` 帧。
- 工作台内置 agent 的会话历史拆成两份：`sessions/<sid>.jsonl` 仍是展示用的，新增
  `sessions/model/<sid>.jsonl` 记录给模型用的历史（含清理、压缩、中断修复）。老会话第一次用到时自动迁移。

### 定时任务定义（M4 第 1 步）

- `schedules.toml` 定义任务：每个任务一个 `[jobs.<名字>]`，字段有 `cron`、`prompt`、`title`、`enabled`、
  `profile`、`cwd`、`allowed_tools`、`notify`、`notify_on`、`timeout`、`max_steps`。文件不存在视为没有任务。
- cron 只收 5 段（分 时 日 月 周）或 `@hourly` / `@daily` / `@weekly` / `@monthly` 这类别名，不收 6 段写法。
- 单个任务写错只影响它自己；只有 TOML 语法错误或顶层出现 `jobs` 以外的键（比如少写个 s 的 `[job.x]`）才整个文件不可用。
  任务引用的 `profile` 会和 `config.toml` 交叉校验，免得半夜触发时才发现跑不起来。
- `sa schedule list` 列出每个任务的下次触发时间，写错的任务标出原因，此时退出码为 1。
- `sa init` 改成「缺哪个配置文件就生成哪个」，两个都在才报错、不覆盖；老用户再跑一次就能补上 `schedules.toml` 模板。
- **注意**：还没有 `sa daemon`，这里定义的任务目前只能查看，不会被执行。

### debug 模式

- 四档 `off / on / verbose / full`：
  - on：每次 API 请求（URL、model、消息条数、工具个数、请求体大小）和响应（状态码、耗时、首 token 延迟、token、
    `finish_reason`），以及每个工具调用（名字、参数、权限等级、判定结果、耗时、结果大小、是否截断落盘）。
  - verbose：再加每轮的消息清单（role + 字符数）和请求开关。
  - full：再加实际发给模型的正文和模型返回的结构（思考、正文、工具调用、usage）。跨轮只打新增的消息，
    工具清单没变时只报个数；工具只打名字和参数字段名，不打整份 schema；参数不是合法 JSON 时会标出来。
    正文预览长度由 `body_chars` 控制（默认 600，0 表示不截断）。
- 三个入口：`config.toml` 的 `[debug]`（`enabled` / `verbose` / `full` / `body_chars`）、`sa --debug [LEVEL]`
  和 `sa run --debug`、REPL 里的 `/debug`。高档隐含低档（`full` 隐含 `verbose`，`verbose` 隐含 `enabled`）。
- debug 输出走 stderr，可以 `2>debug.log` 单独存。API 失败和被中断的请求也有事件，这两种以前看不到。
- 工作台的 SSE 新增 `api_request` / `api_response` 两种帧（前端还没展示）；full 档的正文不推给前端。

### 工作台

- 空间会话里模型的回复改用 Markdown 渲染（零依赖手写渲染器）：标题、有序 / 无序 / 嵌套列表、任务列表、
  表格（含对齐）、引用、分隔线、代码块、粗体 / 斜体 / 删除线、链接、裸网址。用户气泡和控制面板的消息详情仍是纯文本。
- 安全：原文每个字符都只转义一次，只有 `http(s)` 链接可点（新标签页打开），**图片不加载**，
  防止 prompt injection 借图片 URL 把数据外发；唯一放行的 HTML 标签是 `<br>`。
- 接入 MCP、上下文清理和压缩，见上面两节。

### 开发环境和日常环境隔离

- 仓库地址换到 `github.com/tjiisztiuv/SimpleAgent`。日常用的 `sa` 改为从 GitHub 装快照：
  `uv tool install "git+https://github.com/tjiisztiuv/SimpleAgent.git@v0.2.0"`，本地改代码不影响它。
- 在源码仓库里 `uv run sa` 是开发模式（包往上两级有 `pyproject.toml` 和 `.git`，git worktree 也算）：
  数据目录自动换成 `~/.simpleagent-dev/`，`sa serve` 默认端口换成 8385，两边可以同时开；
  `sa --version`、REPL 和 `sa serve` 启动时都会标出来。
- 优先级：`SIMPLEAGENT_HOME` > 开发模式 > `~/.simpleagent`。

## 修复

- REPL 的 `/clear` 之前没落盘，`--resume` 后清掉的历史又回来。
- 工作台中断正在执行的工具后留下没有结果的 `tool_call`，下一条输入会被 API 拒绝；已经坏掉的老会话在迁移时自动补齐。
- `[debug]` 里只写 `verbose = true` 不生效（之前要同时写 `enabled = true`）。
- debug 模式下流式正文的最后一行和响应状态挤在同一行。
- `npx -y <包>` 联网查 npm 仓库卡住、一行输出都没有时，之前提示「再试一次就好」，
  现在建议在 args 最前面加 `--prefer-offline`（或全局安装后换成装好的命令）。
- `sa --version` 里带路径的输出不再被终端宽度折行。

## 升级

```bash
uv tool install --reinstall "git+https://github.com/tjiisztiuv/SimpleAgent.git@v0.2.0"
sa --version                     # simpleagent 0.2.0
sa init                          # 补上 schedules.toml 模板（config.toml 已存在会跳过）
```

- 之前用 `uv tool install --editable .` 装的，也用上面这条换成快照，否则日常用的就是开发中的代码。
  用源码跑的，拉代码后要 `uv sync` 装上新依赖 `croniter`。
- `config.toml` 里的新段（`[context]`、`[debug]`、`[mcp_servers.*]`）都有默认值，不加也能跑；
  老配置不会自动补上示例，对照 `sa init` 生成的模板（`src/simpleagent/config.example.toml`）手动加。
- 用本地 Ollama 的，检查 `[profiles.local]` 的 `context_window` 是否和 Ollama 实际的 `num_ctx` 一致：
  Ollama 超长时悄悄截断而不报错，不一致的话清理和压缩的预算会算错。
- 工作台的老会话第一次打开时自动迁移成两份历史，不用手动处理。
- 在源码仓库里第一次 `uv run sa` 要单独 `uv run sa init`；API key 可以和日常共用：
  `ln -s ~/.simpleagent/.env ~/.simpleagent-dev/.env`。以前开发时写进 `~/.simpleagent/` 的测试数据不会自动分离，要自己清理。
- `v0.2.0` 这个 tag 在发布当天重打过一次，把 MCP 按需启动也收了进来。之前装过 v0.2.0 的，
  用上面的 `--reinstall` 重装一遍才能在配置里用 `start = "lazy"`（老快照不认识这个字段，会报未知配置项）。

### 退回 v0.1.0 时要注意

- 配置模型不接受未知的键：`config.toml` 里加了 `[context]`、`[debug]`、`[mcp_servers.*]` 的话，v0.1.0 会报错，要先删掉。
- 会话 JSONL 新增了 `replace`、`compact` 两种记录，v0.1.0 会忽略它们，恢复出来的是清理、压缩之前的原文，可能超长。

## 已知限制

- **定时任务还不会自己跑**：M4 只做了任务定义，`sa daemon`、通知、`web_fetch` 都还没做，
  这一版仍要自己用 cron / launchd 调 `sa run`。
- **MCP 只支持本机 stdio server**：远程 HTTP 和 OAuth 的 server（日历、邮件、IM 大多是这种）
  等引入官方 `mcp` SDK 时再做。
- **权限规则还没进配置文件**，`--allow` 只认工具名，不支持模式匹配。
- **外部 CLI 执行者没有实时审批**：Claude Code / OpenCode 的空间仍只有只读和全放行两档。
- debug 的 SSE 帧前端还没展示，full 档正文只在终端里看。
- 记忆、Skills、子 agent 都还没做，见 [路线图](../ROADMAP.md)。

## 下一步

M4 剩下的步骤：跑一次任务和运行日志 → 通知 → `web_fetch` → `sa daemon` → 让模型管理任务的工具 → launchd 常驻。

## 质量

- 604 个测试（v0.1.0 是 314 个），全部离线（FakeLLM、录制样本、假 MCP server），不访问网络，也不依赖本机装没装外部 CLI。
  Markdown 渲染器的测试要本机有 `node`，没有就整体跳过。
- `ruff check` 和 `ruff format` 干净。
- `tests/serve/test_web.py::test_pinned_session_stays_on_top` 偶发失败（同一毫秒创建的会话排序不稳定），v0.1.0 就有，还没修。
